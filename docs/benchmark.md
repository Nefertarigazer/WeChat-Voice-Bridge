# 模拟消息延迟基准

本次 Release 基准使用 Windows 11 Build 22631、发布包内置的 Python 3.12.10 和本机模拟 SQLite WAL 数据。每组 30 条，使用固定种子，每次等上一条到达后随机等待 20–179 ms，再提交下一条。该到达节奏与轮询周期相关。百分位使用最近秩法，P99 在 30 条样本中等于最大值。

**检测延迟**由 Python 同一进程的单调时钟测量，从合成 SQLite 写入提交返回到查询读出（模拟 T0 → T3）。测试另外确认 30 条均到达 C#，没有漏读或重复，最后 Worker 退出且夹具目录清理完毕。所有时长单位为毫秒。

六组共 180 条均通过，缺失、重复和测试路径中的 API 错误计数均为 0。此基准使用合成与播放替身，云端请求数为 0。默认事件模式在该负载下取得更低的发现延迟。一次运行不足以为真实微信选择参数。

## 资源样本

- Worker 的期末工作集约 17.8–18.6 MiB。父进程为 xUnit 宿主，约 85.6–87.0 MiB。
- Worker 的短窗口 CPU 记账本轮读数为 0 ms。父进程每组记录 0–93.75 ms，含测试宿主活动。读数受 Windows 记账粒度影响。
- Worker 的 Windows 进程 I/O 读计数每组约 500 kB，写计数约 385 kB，含 IPC 与文件操作。物理磁盘 I/O 未单独采集。
- `artifacts/benchmark.json` 保留每组原始汇总。运行 `scripts/Test.ps1 -Benchmark` 可复测。

## 计时边界

文件通知、C# 查询发起和 C# 接收使用 C# Stopwatch 口径，可在 Benchmark 界面查看。SQLite 查询耗时和模拟发现耗时各自由 Python 单调时钟计算，两个进程的原始计数值不直接相减。文件通知时间也不等于事务提交。

真实 Fish normal、balanced、low 的首帧、音质及耗时均为 **NOT TESTED**。合成代码记录请求路径到首个可解析 MP3 帧或 PCM 采样、到 WASAPI 提交及播放完成的时间。WASAPI 提交属于软件侧代理指标。手机发送时间、真实微信到达时间、扬声器实际首音和整条端到端延迟尚无可信测量。
