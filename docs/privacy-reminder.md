## 1. 用户要求（原话整理）

**最初（2026-11-11）**
- 隐私模式：不读消息内容，改说「您收到了一条消息」；可以自定义，默认「谁谁谁给你发了一条消息」。
- 提醒模式：用户没回复时，在第 1、3、5、7、10、15、20 分钟各提醒一次，之后每 5 分钟一次，到 1 小时为止；检测到用户自己回复就停；隐私模式下要说条数（「您微信收到了几条信息」）。
- 两个模式都用首页上的按钮开关。

**补充（2026-11-11 下午）**
- 难点是把两个按钮放到合适的位置，**美观最重要**。
- 自定义设置要巧妙融进去：界面依旧整洁，又不会藏得很深，页面不能变丑。
- 要切身想用户在哪些情况下开这两个模式。
- 画风、设计思路与现有设计统一，保持偏苹果的清新高级；为此可以适当改善整体布局，但必须美观合理。
- 除了回复，用户也能在界面上直接把某个联系人「标为已读」；用户已经回复的，自然算已读。
- 可以借鉴 GitHub 上类似的微信消息提醒项目和更好的思路。

## 2. 现状（代码事实，2026-11-11 调查）

**消息管线**
- worker 只读 `message_N.db` 与 `contact.db` 的快照副本；新消息查询在 `worker/wechat_adapter.py` 的 `WeChatStore.query()`，SQL 用 `real_sender_id IN (SELECT rowid FROM Name2Id WHERE user_name = 对方)` **只取对方发来的**；`last_incoming_text()` 同样过滤。
- 允许的类型 `TEXT_ROWS`：1 文本、3 图片、47 表情、49/57 引用回复。语音、视频、文件、链接不读。
- 游标：每个（联系人, 分片）一个 `local_id`，`ack` 才提交；开始监听时以 `MAX(local_id)` 为基线，停止期间的消息与回复都看不到。
- 群聊在四层被拒（main.py、open_conversations、PythonFixtureSource、SessionController.Start）；朗读对象只能是 1–8 个私聊联系人。
- 没有未读数：不读 `session.db`。「已读」只能是本应用里的状态（微信端只读，不能改）。
- `SessionController.Admit` 只收 `Incoming`；去重按消息 key；入队后发 `Processed("已接收", 预览, ConversationId)`。
- 朗读文本：worker `render_speech`（词库等）→ `RoutedSpeech.Resolve`（MainWindow.Library.cs）里 `ContactProfile.Prepare` 加提示词（如「张三说，…」）。隐私模板最适合放在这里。
- 队列：有界 Channel，单消费者，无优先级；没有「插入一条合成播报」的公开接口，提醒需要新增类似 `Announce` 的入口，保证仍是单线程播放。
- 朗读记录：只是字符串（`HH:mm:ss   内容`），最多 40 条，不持久化，不带联系人 id。隐私模式下还会显示消息预览（设置里「朗读记录显示消息内容」开着时），需要一并处理。
- 设置：`LocalSettings`（`%LOCALAPPDATA%\WeChatVoiceBridge\settings.json`），record + init 默认值，枚举存数字（只能末尾追加）。

**首页布局（MainWindow.xaml）**
- 窗口 940×780（最小 780×600），左栏 204，右侧内容最大宽 660。
- 自上而下：标题「首页」(30) → 状态卡（左：状态标题 22 + 说明；右：开始/结束主按钮；空闲时中间约 500 DIP 空白）→「朗读对象 · n/8」+「＋ 添加」→ 联系人卡片（宽 ≥572 时两列，每卡含头像、名字、试听/移除、音色、模型、提示词）→「朗读记录」标题行（右侧两个空列）→ 记录卡（列表高 138，右上角垃圾桶）。
- 默认窗口、两位联系人时**正好不滚动**（历次标定的硬约束）；加高任何东西都会触发滚动。
- 现有可复用件：iOS 风格 `Switch`（46×28）、`Segment` 分段控件、`RowMenu` 白底圆角菜单、`DialogShell` 对话框、`Disclosure` 平滑展开、底部字幕提示 `HintToast`、各色药丸按钮。

## 3. 调研（2026-11-11，两份网上调研，来源已转述）

**结论先说**：GitHub 上没有找到成熟的「微信未回复提醒」项目（现有的多是机器人或已失效的网页版微信脚本，例如 [wxauto](https://github.com/cluic/wxauto) 只做界面自动化监听）。可借鉴的成熟设计来自通用通知工具、苹果 / 安卓系统和企业微信客服工具。

**开源项目**
- [Telegram Android](https://github.com/DrKLO/Telegram)：「重复通知」可选 5/10/30 分钟或 1/2/4 小时；「智能通知」限制一段时间内最多响几次；可按会话设例外。
- [MissedNotificationsReminder](https://github.com/httpdispatch/MissedNotificationsReminder)：重复间隔 + 最多次数；按时段启用；通话中、静音时不提醒；有一个「停止提醒」入口，不必逐条清除。
- [VoiceNotify](https://github.com/pilot51/voicenotify)：朗读通知；可编辑播报模板、文本替换、关键词过滤、免打扰时段；屏幕关着时才重复。
- BuzzKill（闭源安卓应用）：冷却（一阵连发只响一次）、「提醒我直到看过」、隐藏内容的「秘密」模式、按联系人设置。
- [Signal #5945](https://github.com/signalapp/Signal-Android/issues/5945)：连发消息的提醒间隔逐步拉长、读过就重置。
- [qiweidoc](https://github.com/zhimaAi/qiweidoc)（企业微信会话存档，开源）：超时未回复阈值 1 分钟到 24 小时；可只在工作时段生效；「无需回复」词表（默认 好的谢谢 / 好的 / 谢谢）外加「包含」匹配，可跳过图片、纯表情、表情包；「已回复」的判断是自己最后一条回复晚于对方的消息。缺点是每条消息各提醒一次，不合并。

**系统与产品**
- iOS 信息「重复提醒」：每 2 分钟一次，最多约 10 次；解锁或查看后停止（[Apple](https://support.apple.com/zh-cn/guide/iphone/iph62faab6a4/ios)）。
- iOS「显示预览」：始终 / 解锁时 / 永不；隐藏预览时只显示「通知」，开发者可让占位文字带条数、可选择保留标题（[HIG 通知](https://developer.apple.com/design/human-interface-guidelines/notifications)）。
- Siri「播报通知」：只在戴耳机且手机锁屏时播报；说出发件人并朗读，长消息只说是谁发来的；按应用开关（[Apple](https://support.apple.com/zh-cn/102536)）。
- 专注模式：只允许选定的人；同一个人 3 分钟内连续来电可突破。
- Gmail「提醒回复」：在邮件旁边写明「3 天前收到，要回复吗？」；Apple 邮件「稍后提醒」「跟进」：提醒放在邮件本身上，时间到了邮件回到最上面；Slack「提醒我」变成带角标的待办。
- 苹果设计规范：开关只用于两种相反状态，最好放在带标签的行里；控制中心式磁贴 = 图标 + 标题 + 可选的状态值，开启时上色；弹出面板（popover）适合少量相关设置、点外面就关、改动自动保存；常用控件放明面，进阶选项放在带标签的展开控件后面；不要因为没回复就反复通知同一件事，否则用户会把通知全关掉。

**我们采纳的想法**
1. 按联系人记「待回复」，不按消息：新消息只增加条数，不重启 1/3/5… 的时间表（避免 qiweidoc 那种一条一响）。
2. 同一时刻到期的提醒合并成一句：「张三和李四的消息还没回」「张三 3 条、李四 1 条」。
3. 提醒要说明是「还没回」，让人一听就知道不是新消息（Gmail 的写法）。
4. 「无需回复」：好的 / 收到 / 谢谢 / 嗯 / OK、单独的表情包与图片，照常朗读，但不触发提醒（qiweidoc 证明可行）。默认开，可在设置里改。
5. 停止条件：自己回复、点「标为已读」、或到时间表的终点；可一键暂停全部提醒。
6. 默认终点：用户给的是 60 分钟（共 15 次）。苹果的经验是约 20 分钟、10 次以内，否则用户会嫌烦。保留用户的 60 分钟时间表为默认，同时给「20 分钟」的轻量选项（见 §5，待用户拍板）。
7. 首页控件做成苹果控制中心式的「磁贴」：图标 + 标题 + 一行状态值，开启时上色；设置用点开即用、自动保存的小面板。
8. 「标为已读」是按钮不是开关，放在「待回复」的人身上。

## 4. 使用场景（用户会在什么时候打开）

**隐私模式**：电脑外放、旁边有人，但仍想知道「谁找我」。
- 办公室、开会、和家人同处一室：伴侣、家人、客户的消息内容不该被别人听见。
- 共享屏幕、录屏、直播：声音会被录进去，屏幕上的朗读记录也会被看到，所以记录里同样不能出现内容。
- 这是**随场合频繁切换**的开关：进会议室打开、回家关掉。所以必须一键可达、状态一眼可见（忘了关比忘了开更糟）。重启后保持原状态，宁可多保护一次。

**提醒模式**：听到了、想回、一投入就忘了。
- 写代码、打游戏、看视频、戴耳机时，伴侣 / 家里老人 / 老板 / 重要客户的消息听过就忘。
- 临时离开座位（倒水、开门），回来时有一句「张三的消息还没回」比翻微信更快。
- 朗读对象本来就是用户挑出来的 1–8 位重要私聊，所以提醒只对他们生效，不涉及群聊（群聊本来也不朗读）。
- 最怕的是「被唠叨」：对方最后一句是「好的」「嗯」或一个表情包时，不该催；同时到期的几位要合成一句说；用户自己回了、或点了「标为已读」，立刻安静。
- 「标为已读」用于：已经在手机上看过但不打算现在回、当面已经说过、或打电话回过了。

## 5. 设计

### 5.1 首页布局：状态卡旁边加两块「模式磁贴」（推荐方案）

借鉴苹果控制中心：一块大的「状态」卡 + 两块同高的小磁贴，排成一行。

```
┌───────────────────────────────┐ ┌──────────┐ ┌──────────┐
│ 正在监听                 [结束] │ │ (锁)   ⌄ │ │ (铃)   ⌄ │
│ 对方发来新消息时会自动朗读       │ │ 隐私模式  │ │ 提醒模式  │
│                               │ │ 只说是谁  │ │ 1 小时内  │
└───────────────────────────────┘ └──────────┘ └──────────┘
```

- **不增加页面高度**：磁贴与状态卡同一行、同高（约 92–96），默认窗口两位联系人时仍不滚动（现有余量约 20）。
- **尺寸与对齐**：内容区 660 时，状态卡 324 宽，正好与下方左侧联系人卡同宽；两块磁贴各 156、间距 12，合起来 324，正好与右侧联系人卡对齐，整页上下成一套网格。状态说明相应缩短为「有新消息会自动朗读」，保证一行放得下。内容区窄于约 640（窗口缩小）时，两块磁贴自动移到状态卡下面并排（此时联系人卡已变成单列，页面本来就会滚动）。

### 5.3 联系人卡片：未回复角标 + 「标为已读」

- 提醒模式打开且这个人有未回复的消息时，头像右上角出现红色圆形角标，数字是未回复条数（与微信本身的未读红点同一种认知）。
- 卡片操作行里原来的「试听」（监听时本来就是禁用的）换成同款药丸「✓ 标为已读」；点了角标消失、这个人的提醒停止。用户在微信里回复后，角标同样自动消失，等同于点过。
- 单人布局（只有一位联系人时）同样处理。
- 托盘右键菜单加两项可勾选的「隐私模式」「提醒模式」，不打开窗口也能切换。

### 5.4 播报规则

**隐私模式**
- 新消息不读内容，按选定方式播报；`{名字}` 取卡片上的名字，并经过词库处理（名字读不准可以在词库里改）。名字里没有可读的字时说「有人」。
- 同一个人的消息还排在队列里没播时合并：「张三给你发了 3 条消息」。
- 朗读记录只显示「张三发来一条新消息」，不显示内容（覆盖设置里的「显示消息内容」）。
- 不监听时点「试听」，读的也是隐私播报句。

**提醒模式**
- 按联系人记「待回复」：对方发来需要回复的消息就进入待回复，时间表从**最近一条**消息算起（对方又发一条，就从这条重新算）。
- 时间表：1 小时档 = 第 1、3、5、7、10、15、20、25、30、35、40、45、50、55、60 分钟（15 次）；20 分钟档 = 前 7 次。
- 停止：自己在这个聊天里发出任何消息（文字、语音、表情、通话都算，手机上回的也算，见 §7）；点「标为已读」；走完时间表；关闭提醒模式；结束监听（结束后看不到回复，干脆清零，重新开始监听只跟踪新消息）。
- 不需要回复的消息（单独的「好的、好、嗯、嗯嗯、哦、收到、谢谢、好的谢谢、OK、拜拜、晚安」，或单独一个表情包）照常朗读，但不会让这个人进入待回复，也不会重算时间表。
- 播报句不含消息内容：
  - 一个人：「张三的消息还没回，已经 10 分钟了」
  - 同一时刻到期的几个人合成一句：「张三和李四的消息还没回」
  - 隐私模式且「不说是谁」：「你有 3 条微信消息还没回」
- 提醒排在正常消息后面播，不打断正在读的消息；这个人的新消息已经在排队时，跳过他这次提醒。
- 朗读记录里记一行「提醒：张三的消息还没回」。

### 5.5 数据与实现要点

- worker：同一个快照上，为每个联系人多查一句「游标之后、发送者不是对方、不是系统消息」的最新一条（只要 `sort_seq`，不读内容），随 `message` 包带回 `replies`。不新增读取任何数据库文件。
- Core：新增纯逻辑的 `ReplyTracker`（待回复、时间表、合并、无需回复判断），可单测；`SessionController` 新增往同一队列插入播报的入口，保证仍是单线程播放。
- 设置（`LocalSettings`，枚举显式编号、只在末尾追加）：`PrivacyMode`、`PrivacyStyle`（说出是谁 / 不说是谁 / 自定义）、`PrivacyTemplate`、`ReminderMode`、`ReminderSpan`（1 小时 / 20 分钟）、`ReminderSkipAcknowledgements`。
- 朗读记录改为带联系人 id 的结构化条目（目前只是字符串），隐私模式与提醒都需要它。

## 6. 实施分节（每节：记 WORKLOG、更新 HANDOVER、单独提交）

1. 只读探针：确认自己发出的消息（含手机端发出、同步到电脑的）在 `Msg_` 表里的 `real_sender_id`、类型与 `sort_seq`，确认系统消息类型。按 AGENTS.md 的探针规则做，只输出计数与类型，不输出内容。
2. worker 返回 `replies` + Python 测试。
3. Core：`ReplyTracker` + 播报入口 + 单测。
4. 隐私模式播报（`RoutedSpeech.Resolve`、试听、朗读记录）+ 设置项 + 单测。
